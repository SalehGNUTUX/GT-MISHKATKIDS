## 2. منطقُ الترتيب

الترتيبُ مبنيٌّ على **الاعتماديّات والمخاطر**، لا على الحجم:

1. **التأسيسُ أوّلًا (v1.8):** ما تَبني عليه الأنشطةُ الجديدةُ (الشاشةُ المخصّصةُ للّعب، التجاوب) + ديونٌ صغيرةٌ معلَّقة — يُنجَزُ مبكّرًا لئلّا يُعادَ العملُ لاحقًا.
2. **المحتوى الجديد (v1.9):** الأنشطةُ المؤجَّلةُ منذ v1.5، على أساسٍ ثابت، في دفعاتٍ متجانسة.
3. **الصوتُ والمحتوى العميق (v1.10):** أعمالٌ تحتاجُ تسجيلاتٍ/توليدًا كثيفًا — تُجمَعُ في إصدارٍ واحدٍ لتقليلِ دوراتِ `gen-piper`.
4. **الأهلُ والبيانات (v1.11):** تقاريرُ وألبومٌ ونسخٌ احتياطيٌّ كامل — **شرطٌ لازمٌ قبل v2.0** (انظرِ التنبيه فيه).
5. **التوزيعُ (v2.0):** التوقيعُ والمتاجر — آخرًا لأنّه يكسرُ التحديثَ للمثبَّتين حاليًّا.

## 4. سيرُ العملِ لكلِّ إصدار

1. نقلُ بنودِ الإصدارِ إلى 🚧 هنا.
2. التنفيذُ دفعةً دفعة → `npm run build` → اختبارٌ محليٌّ من المستخدم (ث1).
3. التزاماتٌ صغيرةٌ بالعربيّة بنمط `<المحور> v1.x: <الوصف>`.
4. قبلَ التحزيم: `git status` نظيفة · `npm run check:icons` · رقمُ الإصدارِ في «حول المشروع» (`index.html`).
5. عند الإصدار: `version` في `package.json` (+أندرويد) · مدخلُ `CHANGELOG.md` · `docs/` و`CLAUDE.md` · بناءُ الحزمِ الأربع (`scripts/build-packages.sh`) · وسمٌ + GitHub Release + SHA256SUMS · الموقعُ (روابطُ وأحجامٌ و«جديد v1.x») · الويكي.
6. تنظيفُ هذا الملفّ من البنودِ المنشورة.
